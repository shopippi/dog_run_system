# ブラウザだけで動くデモ(apps/demo)

Cloudflare のアカウントがなくても、ブラウザだけでこのシステムを本物の動きで触れるデモ。
静的なファイル(HTML・JS)だけで動き、クラウドの API は呼ばない。
お客さん向け画面(apps/liff)と受付・管理画面(apps/admin)は本物の画面をそのまま使い、
API(apps/api の Hono)とデータベースの処理(SQLite)もブラウザの中で動かしている。

`docs/demo.html` は打ち合わせ用に手で作った画面の模型。こちらは実装したシステムそのものが動く。

## 開き方

```sh
pnpm install
pnpm --filter @dr/demo build              # apps/demo/dist/ にできる
npx http-server apps/demo/dist -p 8796    # http://localhost:8796/ を開く
```

- `apps/demo/dist/` の中身を、そのまま静的なファイルの配信先(Cloudflare Pages、GitHub Pages など)に置いても動く。パスはすべて相対パス。
- https か localhost で開く(パスワードの処理にブラウザの暗号の機能を使うため、http の別のアドレスでは動かない)。
- SQLite の本体(WASM、約650KB)はビルドに同梱している(`dist/sql-wasm.wasm`)。読めないときだけ cdnjs、jsDelivr の順に読む。
- 新しめの Chrome・Safari・Edge・Firefox で動く。

## 画面の構成

- 上: 打ち合わせ用の手順(8つの場面)。押すと、その場面に必要な状態まで進める。
- その下: デモの「今日」の日付と、「翌日にする」「夜間の処理を今すぐ動かす」「最初からやり直す」。
- 左: お客さんのスマホ(LINE の中で開く画面)。上で LINE のアカウントを切り替えられる。
  - 「受付の QR を読み取る」: 受付の QR コードを読み取ったときと同じ画面(チェックイン)を開く。
  - 「リッチメニューから開く」: 会員証を開く。
  - 「LINE のトーク」: 家族の招待を送ると、ここに届く。「この招待を開く」で、いま選んでいるアカウントで開く。
- 右: 受付・管理画面。「ログインする人」で受付スタッフ・管理者・製作者を切り替える。

## 手順(打ち合わせ用)

| | 場面 | 使うもの |
| --- | --- | --- |
| 1 | はじめてのお客さん | 「はじめての人」のアカウント。写真は手元の画像を選べる |
| 2 | 9ポイントのおうちがチェックイン | こむぎママ(DR-000001、9ポイント)。10ポイントで無料券が出る |
| 3 | ママがパパを招待 | こむぎママ → LINE のトーク → こむぎパパで開く |
| 4 | パパも同じ日にチェックイン | こむぎパパ。同じ日はポイントが増えず、犬の追加だけ |
| 5 | 別々のおうちを、招待からまとめる | taka_papa(DR-000002)から届いた招待を nico.mama(DR-000003)が開き、その場でまとめる。管理画面は操作ログ(お客さんの操作として残る) |
| 6 | 名前・写真・ポイントを管理者が変更 | こむぎ・だいずのおうちの詳細 |
| 7 | 旧カードの引き継ぎ申請と承認 | ももママ(DR-000004)。紙のスタンプカードの写真つきの申請が確認待ち |
| 8 | 受付・製作者の権限 | 受付スタッフ・製作者でログインし直す |

5〜7 の管理画面(統合・確認待ち・おうちの詳細)は、その機能ができてから動く。それまでは「準備中」と出る。

## ログイン

| 役割 | メールアドレス | パスワード |
| --- | --- | --- |
| 受付スタッフ | staff@example.com | demo-password-1234 |
| 管理者 | admin@example.com | demo-password-1234 |
| 製作者(見るだけ) | developer@example.com | demo-password-1234 |

## 初期データ

- おうち 30 件(犬 1〜3 頭、家族が2人のおうち 5 件)。うち DR-000001〜DR-000004 は手順で使う固定のおうち。
- 来場 半年分(およそ 600 件。土日に多く、雨の日は少なく、イベントの日は多い)と、会員以外の来場。
- ポイントと無料券は台帳どおり(来場ごとに +1、10 ポイントで無料券、使った券もある)。
- 天気 半年分、2026 年の祝日、イベント 4 件、休業日 2 件、確認待ち 1 件(旧カードの引き継ぎ申請)。taka_papa から nico.mama への、まだ開いていない家族の招待 1 件。
- 犬の写真は、最初の 10 おうち分だけ、簡単な犬の絵を使う。

乱数は固定の種から作るので、やり直すたびに同じデータになる(日付だけは、その日の「今日」に合わせて動く)。

## できること

- お客さんの登録(写真つき)、チェックイン、会員証、犬の追加・変更、家族の招待と参加、招待からおうちをまとめる。
- 受付の今日の来場、取り消し、代理チェックイン、会員以外の頭数、おうちを探す。そのほか実装済みの管理画面のすべて。
- 「翌日にする」で日付を進め、翌日のチェックインや、無料券が出る流れを見せられる。
- データはブラウザの中(IndexedDB)に保存され、再読み込みしても続きから使える。「最初からやり直す」で初期データに戻る。

## できないこと・本物との違い

- 本物の LINE ではない。LINE のログイン・トークへの送信・カメラでの QR の読み取りは、デモの画面の中のまねで動く。
- 犬の写真は本物ではない(初期データは絵。自分で選んだ画像は使える)。
- データはこのブラウザの中だけにある。ほかの人やほかの端末とは共有されない。ブラウザのデータを消すと消える。
- 天気・祝日の自動取得など、外のサービスにつなぐ処理は動かない(「夜間の処理」は、つながずにできる分だけ動く)。
- 受付の「今日の来場」は、本物では30秒ごとに新しくなる。デモでは、お客さんがチェックインするとすぐに読み込み直す。

## しくみ(開発者向け)

- `apps/demo/src/engine/`: `createApp()`(apps/api)をブラウザで動かす。D1 の代わりは sql.js の上の `DemoD1`、R2 の代わりはメモリの `DemoR2`。マイグレーションは `apps/api/migrations/*.sql` を番号順に当てる。
- ブラウザの Request / Response は Cookie と Set-Cookie を捨てるので、API に渡す Request のヘッダーを差し替え、Response は Set-Cookie を保つ形にしている(`http-patch.ts`)。管理画面のクッキーは画面ごとの入れ物で保つ。
- 画面との橋渡し: apps/liff と apps/admin は、`VITE_DEMO=1` でビルドしたときだけ `fetch` を差し替え(`src/lib/demo-fetch.ts`)、`/api/` と `/admin/api/` への要求を親の画面に `postMessage` で送る。URL はハッシュ(`#/checkin`)になる。
- 時刻: 要求に `x-debug-now` を付けて、デモの「今日」を API に伝える(`ENVIRONMENT=local` のときだけ効く)。
- テスト: `pnpm --filter @dr/demo test`(D1 の代わりと初期データ)、`npx playwright test --project=demo`(画面の通し操作。デモは `E2E_PORT + 500` 番で配信する)。
