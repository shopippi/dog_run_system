# 2026-10-31 の依頼主の決定(預かり・お泊まりの予約)

`docs/requirements.md` の 21章(と 1・9・10・11・12・14・20章)に反映した。この文書は決定の記録。

## 1. 確定のしかた

- 預かったことのある子(預かり・お泊まりのどちらかで、受付で利用開始にしたことがある子)だけの予約は、すぐ確定する。紙の台帳のころの子は、管理者が「預かり経験あり」の印を付ける。
- はじめての子がいる予約は「確認待ち」にし、お店が管理画面で承認・お断りする(お客さんへの一言を添えられる)。
- 設定「すべて承認制にする」(初期値は off)で、すべての予約を確認待ちにできる。

## 2. 受け入れる頭数はサイズごと

- 預かりは1日あたり、お泊まりは1泊あたり、小型・中型・大型ごと。初期値は両方とも 小型5・中型3・大型2(設定で変えられる)。
- 日ごとに、休み・増減ができる(管理者が予約カレンダーで)。
- 確認待ちも枠を押さえる。お断り・キャンセルで空く。同時に最後の1枠を取っても、二重にはならない。

## 3. お知らせ

- LINE で知らせるのは、確定したとき(すぐ確定・承認)とお断りしたときだけ。前日のお知らせなどは送らない。
- Messaging API のプッシュ(チャネルアクセストークンは wrangler の secret `LINE_MESSAGING_TOKEN`。GitHub の Environment「Secret」に入れる)。トークンがない・送れないときも予約は止めず、結果を記録する。無料のプランの月200通に気をつける(設定で上限)。

## 4. 料金(目安だけ。支払いは受付)

- 預かり(1日): 小型 3,000円、大型 5,000円。お泊まり(1泊): 小型 10,000円、大型 15,000円。
- 中型は未定。仮に間をとって 預かり 4,000円・お泊まり 12,500円(20章で確認)。
- 半日の料金は使わない(初期値 off。上は1日の料金)。
- 画面には「目安。お支払いは受付で」と出す。

## 5. 依頼主の回答(同じ日の追加)

- **中型の料金**: 未定。仮に 預かり 4,000円・お泊まり 12,500円 のまま(管理者が予約の設定で変えられる)。20章に「仮(依頼主が未定のため)」。
- **半日**: 半日も1日と同じ料金。半日の料金の設定は off のまま。
- **預け・お迎えの時間と定休日**: 管理者が予約の設定で変える。予約カレンダーの上に「預け・お迎え 9:00〜18:00 / 定休日 なし」と出し、定休日は灰色。日のパネルと今日の来場の画面に「預け・お迎え」(お泊まりのチェックイン・チェックアウトを含む)を時刻の順に出す。受付スタッフも見られる。
- **当日の予約**: LINE からは受けない(いまのまま)。受付・管理者の手入力では今日も入れられ、お客さんの予約できる期間より前の日も入れられる(過ぎた日はだめ)。
- **確かめてもらうこと**: いまの文のまま決定。
- **お断りのお知らせ**: 送る(いまのまま)。
- **紙の台帳のころの子**: お客さんが LINE で登録し、管理者がワンちゃんごとに「預かり経験あり」を付ける。おうちの詳細に印を出し、確認待ちを承認するときに「この子を預かり経験ありにする」を選べるようにした。
- **登録した情報を使う**: 予約では、飼い主の名前・ワンちゃんの名前・犬種を入れ直させない(LINE の登録のまま)。管理画面の予約には、登録したワンちゃんの名前・犬種・サイズ・写真と、飼い主の名前を出す。

## 6. 見直しで直したこと(安全と正しさ)

- 受け入れ数の見張りの文を、泊数が長くても D1 の「1つの文に値は100個まで」に収まる形(JSON 1つ)にした。
- 予約とキャンセルの、おうちごとの1日の回数の上限(設定。初期値10回)。LINE のお知らせのひと月の上限は、送る前に枠を取る形にした(同時でも超えない)。
- 同じワンちゃんの重なる予約を、batch の中の見張りで防ぐ(元に戻すときも)。
- 送り直しで同じ予約を返す(お知らせも1回だけ)。
- 受付スタッフが見られる来場の一覧は今日の分だけ(ほかの日は 403)。
- AI に渡す分析パックの説明行: メモの列はスタッフが書いた文のままなので、渡す前に確かめるよう書いた。犬種の自由入力は「その他」にした。
